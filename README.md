# 発注アプリ（販売店向け・パイロット：株式会社青山商店）

LPガス器具の**発注を販売店のスマホから行う**ための単体アプリ。価格照会ビューアの派生。

- 販売店ごとに1ビルド。中身は AES で暗号化。合言葉を知る人だけが使える。
- 公開URL（GitHub Pages）に置いても、合言葉がなければただの暗号文。
- 一度開けば以降はオフライン動作（カタログは HTML に埋め込み済み）。
- 「注文を送る」を押すと、**注文書PDF（注文書＋注文請書の用紙全体）を自動生成**し、端末の共有メニュー（LINE・メール・SMS 等）で**PDF添付＋文面**として送れる。サーバー・第三者サービスを一切通さない（PDF生成もブラウザ内。html2canvas を同梱、日本語もそのまま描画）。
- 在庫・発注履歴は **その端末のブラウザ内**（localStorage）に保存。バックアップ書き出し/読み込みで別端末へ移せる。

## 画面（6タブ）

| タブ | 内容 |
|---|---|
| **発注** | ①履歴から追加／②手入力で追加。注文番号は入力欄＋自動採番。→「注文を送る」＝注文書PDF（用紙全体・注文請書欄は空欄）を作って共有メニューでPDF添付送信。／「注文書プレビュー（全体）」でPDF保存・印刷も可。**ページを再読み込み（F5等）すると、未読の有無に関わらず必ずこの発注タブから開く** |
| **お知らせ** | 当社からの連絡事項を日付付きで一覧（過去分も残る）。未読はタブに件数バッジ、重要なものは赤く強調 |
| **見積もり** | 当社が作った見積書（PDF/Excelなど）の一覧。タップでファイルを開く（**index.html の中に合言葉で暗号化して埋め込まれているので、開いた後は完全オフラインで見られる**）。任意の明細を付けておくと「この内容で発注に追加」でそのまま発注タブへ。未読バッジあり |
| **期間** | 開始日・終了日を指定して、その間に買った商品を**全件**一覧表示（builderの取り込み期間内の全取引を保持）。行をタップで詳細→「この内容で発注に追加」 |
| **在庫** | カタログから商品を自動生成。使用 −N ／ 入荷 +N ／ 棚卸し。変更履歴つき。バックアップ/復元。 |
| **履歴** | 送信した注文の控え（送信済 / 確認済 チェック、メモ、再発注、もう一度送る、文面コピー）。CSV書き出し。**当社が納期回答（出荷日・納入日予定）を登録すると、該当注文に「回答あり」表示**。履歴タブに未読件数バッジ。 |

※ お知らせ・見積もり・履歴の未読はタブのバッジ件数で確認できる。以前は未読があると自動でそのタブに切り替わる仕様だったが、2026-09-13に「ページ更新時は常に発注タブから開始する」方式に変更した。

注文書PDFは当社ひな型の用紙**全体**を再現：
上「注文書」＝発注日/会社名/担当者＋明細（注文番号・メーカー・品名・型式（ガス種）・数量・定価・単価・金額・備考・現場名）＋合計金額。
下「注文請書（納期回答）」＝御中・岩谷連絡先まで印字し、日付・出荷予定・送料は空欄（当社が記入）。
※「金額」列は照合の助けとしてアプリ側で追加（紙様式には無い）。合計金額は注文書には表示しない（発注タブの画面上でのみ確認用に表示）。

## 毎月の更新手順（当社）

1. 基幹システムから **この販売店ぶんだけ** の購入履歴を **CSV** で書き出す（計上日・品目コード・品目名称・数量単位・数量・売上単価・請求先名称など）。期間は直近12ヶ月が目安（builder の「直近何ヶ月」既定=12、最大36）。
2. PC で `builder.html` を開く。
3. CSV をドラッグ＆ドロップ → 列の対応づけを確認 → 「集計してプレビュー」。
   - 「複数の得意先が含まれています」と出たら、その販売店ぶんだけに絞って出し直す。
4. 会社名・注文番号プレフィックス・受注メール・（任意）LINE公式アカウントの友だち追加URL/表示名 を確認 → 合言葉を入力 → 「index.html を生成してダウンロード」。
5. GitHub の `.../upload/main` から `index.html` を上書き Commit。
6. 2〜3分後、販売店のスマホで最新カタログ・単価になる。

## 複数人で使うときの注意（衝突対策）

お知らせ・見積もりは「今の index.html を読み込む→編集→書き出す」方式なので、**2人が同時に作業すると、後からアップロードした方が先の変更を消してしまう**リスクがあります（お互い相手の変更を知らないまま古い状態から書き出すため）。

これを軽くするため、`notice-tool.html` / `quote-tool.html` / `reply-tool.html` はいずれも**書き出す直前に、公開中の最新 index.html を自動で取りに行き、そこに自分の追加・削除・上書きだけを重ねて**から書き出します（画面に「✓ 公開中の最新版を確認しました」と出ます）。これにより、**自分が読み込んだ後に誰かが別の内容を先に公開していても、その変更は基本的に残ります**。

ただし GitHub Pages の反映には数分かかるため、**ほぼ同時（数分以内）の作業では取りこぼす可能性が残ります**。実運用では、できれば「今から見積もりアップロードします」とLINEなどで一声かけてから作業するのが確実です。

## お知らせの更新（CSV不要・すぐできる）

年末年始の休業案内や価格改定など、急ぎの連絡をしたいときはこちら。

1. PC で `https://iwbea2012-prog.github.io/lpgas-order-pilot/notice-tool.html` を開く
2. 今の `index.html`（GitHubからダウンロードするか、手元にあるもの）をドラッグ＆ドロップ → 合言葉を入力 → 「開く」
3. お知らせを追加（日付・タイトル・本文・重要フラグ）。既存のお知らせの削除もここで
4. 「最新版と統合して index.html を書き出す」→ GitHubの `.../upload/main` で上書きCommit

カタログ・在庫データ・見積もりには一切触れません（書き出し時に最新のものをそのまま引き継ぎます）。合言葉は基本そのまま（変更したい場合だけ画面下部で新しい合言葉を設定）。

毎月のCSV更新（`builder.html`）を行うときは、生成画面で「現在の index.html」を選ぶと、既存のお知らせ・見積もり・納期回答をそのまま引き継げます（省略すると新しい index.html のお知らせ・見積もり・納期回答は空になります）。

## 見積もりの届け方（販売店からの見積依頼への対応）

見積依頼そのものは電話・LINEなどアプリ外で受け付ける前提。**出来上がった見積書を届ける部分だけ**をアプリでカバーします。見積書ファイル本体は**index.htmlの中に合言葉で暗号化して埋め込み**ます（リポジトリは公開ですが、合言葉を知らなければ中身は読めません）。

1. いつもどおり見積書をExcelで作成する（作成フローは変えない）
2. PC で `https://iwbea2012-prog.github.io/lpgas-order-pilot/quote-tool.html` を開く
3. 今の `index.html` をドラッグ＆ドロップ → 合言葉を入力 → 「開く」
4. 日付・件名・物件名（任意）を入力
5. 明細を入力する。**Excelの見積書で明細の範囲（品名及び仕様／定価／数量／掛率／単価／金額の6列・見出し行を含めない）を選択してコピーし、貼り付け欄にペースト→「貼り付けた内容を明細に反映」**すると自動で行が展開される（1行ずつ手入力も可）。**仕入単価・仕入金額・粗利率などの社内専用の列は絶対にコピー範囲に含めないこと**（範囲に含めなければ、そもそもアプリには一切送られない）
6. 明細を確認・修正（複数行にまたがる品名などは1行にまとめる／不要な空行は削除）→「＋ この見積もりを追加」
   - 見積書ファイルを添付しなければ、**明細から当社の見積書ひな型と同じ書式のPDFを自動生成**して埋め込む（Excelファイルそのものはアップロードしない＝仕入金額が紛れ込む心配がない）
   - 従来どおりPDF/Excelファイルを手動で添付することも可能（この場合は添付ファイルが優先される。Excelをそのまま添付する場合は、シート内に仕入金額など見せたくない情報が残っていないか必ず確認すること）
7. 「最新版と統合して index.html を書き出す」→ GitHubの `.../upload/main` で `index.html` を上書きCommit

アップロードは `index.html` の1つだけです（見積書ファイルは中に埋め込まれています）。ファイルが大きいほど `index.html` 全体が重くなるので、**不要になった見積もりは `quote-tool.html` の一覧から削除**しておくと軽く保てます（画面に現在のおおよそのデータ量が表示されます）。

## 注文請書（納期回答）の登録

販売店から届いた注文書PDFに対して、出荷日・納入日予定を回答します。

1. 届いた注文書PDFの**注文番号**を確認
2. PC で `https://iwbea2012-prog.github.io/lpgas-order-pilot/reply-tool.html` を開く
3. 今の `index.html` をドラッグ＆ドロップ → 合言葉を入力 → 「開く」
4. 注文番号を転記し、出荷日・納入日予定を入力 →「＋ この内容を登録」
5. 「最新版と統合して index.html を書き出す」→ GitHubの `.../upload/main` で上書きCommit

販売店側は**履歴タブの該当注文**に自動で紐付いて表示されます（注文番号で照合）。同じ注文番号にもう一度登録すると、内容は**上書き**されます（最新の回答だけが残るシンプルな仕組み）。カタログ・お知らせ・見積もりには触れません。

## セキュリティ

- 合言葉は長めに（日本語や英単語4語以上、12文字以上推奨）。
- カタログは**その販売店のデータだけ**を含める。
- **CSV（平文の実データ）は絶対にコミット／アップロードしない。** `.gitignore` で `*.csv` を除外済み。
- `builder.html` は CSV をローカル処理するだけで、外部送信は一切しない。
